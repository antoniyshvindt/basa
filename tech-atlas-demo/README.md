# Технологический атлас · LPBF (демонстрационный макет)

Интерактивный HTML-прототип аналитической системы «Технологический атлас» на примере промышленной установки лазерного сплавления металлических порошков (Laser Powder Bed Fusion, LPBF / СЛП).

Это демонстрационный макет, а не платформа: нет сервера, базы данных и авторизации. Все данные лежат локально в `data/*.json`. При показе внешние API не нужны.

## Запуск

**Проще всего:** откройте `dist/tech-atlas-lpbf.html` — это один самодостаточный файл (~1,4 МБ) со всеми данными, стилями и библиотеками. Он открывается двойным щелчком в любом современном браузере (Chrome, Edge, Firefox, Safari) на компьютере, планшете или телефоне, без сервера и интернета. Пересборка: `node tools/build-single.mjs`.

**Из исходников:**

Сборка не нужна. Нужен любой статический HTTP-сервер, потому что данные загружаются через `fetch`:

```bash
cd tech-atlas-demo
python3 -m http.server 8000
```

Затем откройте http://localhost:8000/. Подойдёт и `npx serve .`. Открыть `index.html` двойным щелчком не получится: браузер заблокирует `fetch` с `file://`.

## Главный сценарий

Изделие → подсистема → узел → технология → ВНТ → выполненные НИОКТР → научные коллективы → патенты → рынок и производители → меры поддержки → технологические дефициты → проект развития.

Выберите узел на схеме (раздел «Анатомия»). Под фигурой появится сквозная цепочка, каждый шаг которой открывает соответствующий раздел.

## Структура

```
tech-atlas-demo/
  index.html            точка входа
  css/app.css           стили (светлая и тёмная темы)
  js/app.js             разделы, маршрутизация, сквозная цепочка
  js/anatomy.js         рантайм фигуры: выбор, разборка, камера, цикл печати
  assets/anatomy/       lpbf.svg и lpbf-model.json (сгенерированы), iso-kit.mjs и iso.css (кит Anatomy, MIT)
  assets/images/        russia-map.json (контур России, Natural Earth)
  assets/vendor/        cytoscape.min.js 3.30.2 (MIT)
  data/                 products, components, technologies, research, organizations,
                        patents, suppliers, support, graph, evidence, publications (.json)
  research/             research-log.md, source-registry.md, gaps.md
  tools/                генераторы: build-anatomy.mjs, build-data.mjs, build-map.mjs, data/*.mjs
```

## Пересборка данных

Исходные данные и аналитика лежат в `tools/data/*.mjs`. JSON и фигура генерируются:

```bash
node tools/build-data.mjs
```

```bash
node tools/build-anatomy.mjs
```

`build-data.mjs` проверяет ссылочную целостность (технологии, узлы, организации) и строит `graph.json`.

## Достоверность

- **ЕГИСУ НИОКТР** опрошена через подключённый коннектор: регистрационные номера, названия, исполнители, заказчики, сроки и РИД — из карточек. Технологии, узлы и релевантность — аналитическая разметка макета, она помечена отдельно.
- Ничего не придумано: где данных нет, так и написано («нет данных», «не подтверждено», уровни подтверждения патентов A–D).
- После расширения сети по первоисточникам проверены: конкурс РНФ № 3052, Приложение VII ЕС (X.A.VIII.005.a), Supplement No. 4 США; через Crossref собраны 153 публикации. Решение № 22-68462-00692-Р (версия 7 от 03.07.2026) сверено по sudact.ru. Не удалось проверить: патентные реестры (сайты отвечают 403/503), OpenAlex (нужен ключ). Подробно — `research/gaps.md`.
- Схема установки — типовая инженерная модель, а не геометрия конкретной коммерческой установки. Свечение ванны и трек — условная визуализация, не физический расчёт.
- В разделе «Рынок» показаны только правовые режимы и категории вывода. Обходные схемы не рассматриваются.
